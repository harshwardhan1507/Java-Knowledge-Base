# Introduction to Spring & Spring Boot

> **Goal:** Understand what Spring Boot is, why it exists, and what happens between an HTTP request and our Java code.

---

## 1. The Big Picture

Before learning Spring Boot, understand one fundamental question:

> How does a client communicate with Java code running on a server?

The basic model is:

```text
Client
   ↓
HTTP Request
   ↓
Server
   ↓
Java Application
   ↓
HTTP Response
   ↓
Client
```

This is called **Client–Server Architecture**.

### Client

The client is the system that requests something.

Examples:

- Web browser
    
- React application
    
- Mobile application
    
- Postman
    
- Android/iOS app
    

### Server

The server receives requests, processes them, and returns responses.

A backend server may:

- Authenticate users
    
- Fetch database data
    
- Apply business rules
    
- Save data
    
- Return JSON
    
- Handle errors
    

The fundamental idea:

```text
Client asks.
Server responds.
```

---

# 2. HTTP — The Language of the Web

For the client and server to communicate, they need a common protocol.

That protocol is **HTTP**:

> HyperText Transfer Protocol

HTTP defines the structure of communication between clients and servers.

It specifies:

- How requests are structured
    
- How responses are structured
    
- Request methods
    
- URLs/paths
    
- Headers
    
- Request body
    
- Response status codes
    

HTTP is an **application-layer protocol** that works over TCP/IP.

---

# 3. Request–Response Cycle

A typical web interaction follows:

```text
Client
  ↓
HTTP Request
  ↓
Server
  ↓
Process Request
  ↓
HTTP Response
  ↓
Client
```

For example:

```http
GET /courses
Host: www.example.com
```

The server interprets this as:

> "The client wants the courses resource."

It processes the request and might return:

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "courses": ["Java", "Spring Boot", "DSA"]
}
```

---

# 4. Anatomy of an HTTP Request

An HTTP request commonly contains:

1. Method
    
2. URL/path
    
3. Headers
    
4. Body
    

Example:

```http
POST /login
Content-Type: application/json
```

```json
{
  "email": "abc@gmail.com",
  "password": "12345"
}
```

### Method

The method describes the intended operation.

|Method|Meaning|Example|
|---|---|---|
|`GET`|Read data|Fetch users|
|`POST`|Create data|Create an order|
|`PUT`|Replace data|Replace user profile|
|`PATCH`|Partially update data|Change phone number|
|`DELETE`|Remove data|Delete an order|

---

# 5. HTTP Headers

Headers contain additional information about the request.

Examples:

```http
Accept: application/json
Content-Type: application/json
Authorization: Bearer <token>
Host: example.com
```

In Spring Boot, headers become important when working with:

- JSON APIs
    
- Authentication
    
- JWT
    
- Request metadata
    
- Content negotiation
    

---

# 6. HTTP Request Body

The body contains data sent by the client.

It is commonly used with:

- `POST`
    
- `PUT`
    
- `PATCH`
    

Example:

```json
{
  "name": "Rohit",
  "email": "rohit@example.com"
}
```

Modern REST APIs commonly use **JSON** for request bodies.

`GET` requests generally do not use a request body.

---

# 7. Anatomy of an HTTP Response

An HTTP response commonly contains:

```text
Status Code
Headers
Body
```

Example:

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "message": "Login successful"
}
```

Important status codes:

|Status|Meaning|
|---|---|
|`200`|Request successful|
|`404`|Resource not found|
|`500`|Internal server error|

More HTTP status codes will become important when building REST APIs.

---

# 8. JVM — Where Java Runs

A normal Java program executes inside the **JVM — Java Virtual Machine**.

Example:

```java
public class Main {

    public static void main(String[] args) {
        System.out.println("Hello World");
    }
}
```

The basic flow is:

```text
.java source
    ↓
javac
    ↓
.class bytecode
    ↓
JVM
    ↓
Program execution
```

The generated bytecode is platform-independent.

This is the foundation behind:

> Write once, run anywhere.

---

# 9. Normal Java Program vs Web Application

A normal Java program often behaves like:

```text
Start
 ↓
Execute instructions
 ↓
Finish
 ↓
Exit
```

A backend application behaves differently:

```text
Start
 ↓
Keep running
 ↓
Wait for requests
 ↓
Process request
 ↓
Send response
 ↓
Wait for another request
 ↓
...
```

A web server is therefore a long-running process that continuously listens for incoming requests.

---

# 10. Why Core Java Alone Isn't Enough

Core Java provides:

- Classes
    
- Objects
    
- Inheritance
    
- Interfaces
    
- Collections
    
- Threads
    
- Files
    
- Networking
    

But Core Java does not automatically provide a complete HTTP application model.

It does not automatically understand that:

```text
GET /users
```

means:

> "Fetch the users resource."

Something has to interpret the HTTP request and connect it to Java code.

---

# 11. Java Can Perform Networking

Java has supported networking since its early versions through packages such as `java.net`.

For example:

```java
ServerSocket server = new ServerSocket(8080);
```

This allows Java to listen for network connections on port `8080`.

But a raw network connection is not automatically a convenient HTTP request object.

A request such as:

```http
GET /users HTTP/1.1
Host: localhost:8080
```

is ultimately transmitted as network data.

The application needs something to:

- Read the connection
    
- Parse the HTTP request
    
- Identify the method
    
- Identify the path
    
- Read headers
    
- Read the body
    
- Route the request
    
- Construct the HTTP response
    

Doing this manually would be tedious.

---

# 12. What Would We Have to Do Manually?

Using only low-level Java networking, we would need to handle things such as:

```text
1. Open a server socket
2. Listen for connections
3. Read incoming bytes
4. Parse HTTP
5. Extract method
6. Extract URL/path
7. Extract headers
8. Extract body
9. Route request
10. Execute application logic
11. Construct HTTP response
12. Handle errors
13. Manage multiple connections
```

We might end up writing routing logic such as:

```java
if (url.equals("/users")) {
    // user logic
} else if (url.equals("/orders")) {
    // order logic
}
```

The problem is that this is **infrastructure code**, not business logic.

We don't want every Java developer to reinvent an HTTP server.

---

# 13. Servlets — The First Important Abstraction

This created the need for a standard mechanism connecting:

```text
HTTP
 ↓
Java
```

That mechanism is the **Servlet API**.

A Servlet is a Java object designed to handle web requests.

Conceptually:

```text
HTTP Request
      ↓
   Servlet
      ↓
 Java Logic
```

Servlets were one of the foundational Java technologies for building web applications.

---

# 14. Servlet Containers

Servlets run inside a **Servlet Container**.

Examples:

- Apache Tomcat
    
- Jetty
    
- Undertow
    

The container handles much of the low-level web infrastructure.

Conceptually:

```text
Client
  ↓
HTTP
  ↓
Servlet Container
  ↓
Servlet
  ↓
Java Application
```

The Servlet Container can handle responsibilities such as:

- Opening a port
    
- Listening for requests
    
- Reading network data
    
- Parsing HTTP
    
- Creating request/response objects
    
- Managing request execution
    
- Calling servlet methods
    
- Sending responses
    

Instead of dealing directly with raw bytes, Java code can work with higher-level web abstractions.

---

# 15. Why Spring Was Needed

Servlets solved the basic problem of Java web communication.

But large applications built directly around Servlets could become difficult to maintain.

Common problems included:

- Boilerplate code
    
- Repeated configuration
    
- Tight coupling
    
- Difficult testing
    
- Difficult maintenance
    
- Complex object management
    

Developers needed a better way to structure large Java applications.

This led to the importance of the **Spring Framework**.

---

# 16. Spring Framework

Spring is a framework/ecosystem designed to make Java application development more maintainable.

Some of its foundational concepts include:

- **IoC — Inversion of Control**
    
- **Dependency Injection**
    
- **Bean Management**
    
- Configuration
    
- Loose coupling
    

A simplified idea:

```text
Without Spring

Class A
   ↓
creates
   ↓
Class B
```

Spring aims to move object creation and dependency management into the framework.

```text
Spring Container
      ↓
creates/manages objects
      ↓
Application Classes
```

These concepts become the foundation for understanding Spring Boot.

---

# 17. Spring Is an Ecosystem

Spring is not a single small library.

It consists of multiple projects/modules.

Important parts include:

```text
Spring Core
Spring MVC
Spring Data
Spring Security
Spring AOP
Spring Boot
Spring AI
```

Each addresses different application concerns.

---

# 18. Spring Core

**Spring Core** is the foundation.

Important concepts include:

- IoC
    
- Dependency Injection
    
- Bean management
    
- Configuration
    
- `ApplicationContext`
    

The Spring container manages application objects called **beans**.

Understanding Spring Core is important because Spring Boot does not eliminate these concepts.

It automates configuration around them.

---

# 19. Spring MVC

**Spring MVC** provides a higher-level programming model for web applications and REST APIs.

Instead of manually writing servlet implementations, we can use controllers and annotations.

Example:

```java
@GetMapping("/hello")
public String sayHello() {
    return "Hello World";
}
```

Conceptually:

```text
HTTP Request
     ↓
Servlet Container
     ↓
Spring MVC
     ↓
Controller
     ↓
Java Method
```

Spring MVC still relies on servlet technology underneath, but provides a cleaner programming model.

---

# 20. Spring Data

Most real applications need persistent data.

At the lower level, Java applications can communicate with databases using **JDBC**.

With JDBC, developers typically have to deal with:

- SQL
    
- Database connections
    
- Statements
    
- Result sets
    
- Resource management
    

This creates a lot of repetitive database code.

---

# 21. ORM, JPA and Hibernate

**ORM** means:

> Object-Relational Mapping

The idea is to map Java objects to relational database data.

For example:

```text
Java Object
    ↕
Database Row
```

### JPA

**JPA — Java Persistence API** is a specification.

It defines rules for persistence and object-relational mapping.

### Hibernate

**Hibernate** is a popular implementation of JPA.

A useful distinction:

```text
JPA       → Specification
Hibernate → Implementation
```

### Spring Data JPA

Spring Data JPA provides another layer that reduces persistence boilerplate.

The conceptual stack is:

```text
Spring Data JPA
       ↓
   Hibernate
       ↓
      JDBC
       ↓
   Database
```

---

# 22. Spring Security

**Spring Security** provides security infrastructure for Spring applications.

It can be used for:

- Authentication
    
- Authorization
    
- Login
    
- JWT
    
- OAuth
    
- Roles
    
- Permissions
    
- Password encoding
    
- CSRF protection
    
- Access control
    

Instead of implementing security infrastructure from scratch, Spring provides established abstractions and mechanisms.

---

# 23. Spring AOP

**AOP — Aspect-Oriented Programming** deals with **cross-cutting concerns**.

These are concerns that affect many parts of an application.

Examples:

- Logging
    
- Security checks
    
- Transaction management
    
- Performance monitoring
    
- Exception-related concerns
    

The goal is to keep such concerns separate from the core business logic where appropriate.

---

# 24. Spring AI

Spring AI is a newer part of the Spring ecosystem for integrating AI capabilities into Java/Spring applications.

It can be used with concepts such as:

- Chat models
    
- Embeddings
    
- Vector databases
    
- RAG
    
- AI providers
    

Examples of providers mentioned in the lecture include:

- OpenAI
    
- Gemini
    
- Anthropic
    

This is particularly relevant when building AI-powered backend services with Spring.

---

# 25. What Is Spring Boot?

This is the most important distinction:

> **Spring Boot is not a replacement for Spring.**

Spring Boot is built on top of Spring and simplifies application setup and configuration.

It provides things such as:

- Auto-configuration
    
- Starter dependencies
    
- Embedded servers
    
- Sensible defaults
    
- Production-oriented features
    
- Reduced manual configuration
    

Instead of spending significant time configuring infrastructure, developers can start building application logic much faster.

---

# 26. Why Spring Boot Feels "Automatic"

Suppose we want to build a web application.

Without Spring Boot, we would have considerably more configuration to manage.

With Spring Boot, adding the appropriate web dependency allows Spring Boot to configure much of the required infrastructure automatically.

Conceptually:

```text
Spring Boot
    ↓
Detect dependencies
    ↓
Apply auto-configuration
    ↓
Configure Spring
    ↓
Start embedded server
    ↓
Run application
```

This is why Spring Boot is often described as **opinionated**.

---

# 27. What Does "Opinionated" Mean?

An opinionated framework provides sensible defaults.

Instead of asking the developer to configure every component manually, Spring Boot makes assumptions based on the application's dependencies and configuration.

For example, a web application can automatically receive configuration involving:

- Embedded Tomcat
    
- Spring MVC
    
- JSON support
    
- Basic web infrastructure
    
- Error handling
    

The important point:

> Spring Boot reduces configuration; it does not eliminate the underlying concepts.

You still need to understand:

- Spring Core
    
- IoC
    
- Dependency Injection
    
- Beans
    
- Spring MVC
    
- HTTP
    
- Servlets
    
- Database concepts
    
- Security
    

---

# 28. Spring vs Spring Boot

|Spring Framework|Spring Boot|
|---|---|
|Core framework/ecosystem|Built on Spring|
|Provides fundamental features|Simplifies Spring setup|
|More manual configuration|Auto-configuration|
|Flexible|Sensible defaults|
|Foundation|Faster application development|

Remember:

```text
Spring Boot uses Spring.
Spring Boot does NOT replace Spring.
```

---

# 29. Where Do Microservices Fit?

Microservices are **not a Spring module**.

They are an **architectural style**.

Instead of building one large application, a system can be divided into smaller independent services.

For example:

```text
                    Application
                         |
       ┌─────────────────┼─────────────────┐
       ↓                 ↓                 ↓
 User Service      Order Service     Payment Service
       ↓                 ↓                 ↓
 Notification       Product Service    ...
```

Each service can potentially be:

- Developed independently
    
- Deployed independently
    
- Scaled independently
    

Spring Boot is commonly used to build these services because creating independent applications is straightforward.

So:

```text
Microservices = Architecture
Spring Boot  = Technology used to build applications/services
```

# 30. The Complete Request Flow

Now connect everything together.

A simplified Spring Boot web request looks like:

```text
Client
  │
  │ HTTP Request
  ↓
Servlet Container
  │
  │ Servlet infrastructure
  ↓
Spring MVC
  │
  │ Route request
  ↓
Controller
  │
  ↓
Service / Business Logic
  │
  ↓
Repository / Data Layer
  │
  ↓
Database
```

Then the response travels back:

```text
Database
   ↓
Repository
   ↓
Service
   ↓
Controller
   ↓
Spring MVC
   ↓
Servlet Container
   ↓
HTTP Response
   ↓
Client
```

Spring Boot sits around this ecosystem and simplifies the configuration required to run it.

# 31. Why Learn the History?

It is easy to write:

```java
@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello World";
    }
}
```

But simply knowing the annotations is not enough.

You should understand the chain underneath:

```text
Client
 ↓
HTTP
 ↓
Servlet Container
 ↓
Servlet
 ↓
Spring MVC
 ↓
Spring Core
 ↓
Spring Boot
 ↓
Your Java code
```

Then Spring Boot stops feeling like magic.

You can reason about:

- Where requests enter
    
- How requests are routed
    
- Where dependencies come from
    
- Where objects are managed
    
- Where business logic belongs
    
- Where database access happens
    
- Where errors occur
    

This becomes extremely useful when debugging real applications.

# 32. Evolution of Java Web Development

The overall progression can be remembered as:

```text
Client–Server Architecture
          ↓
         HTTP
          ↓
   Java Networking
          ↓
 Manual HTTP Handling
          ↓
       Servlets
          ↓
 Servlet Containers
          ↓
   Spring Framework
          ↓
    Spring Ecosystem
          ↓
     Spring Boot
```

Each layer solved a problem introduced by the previous approach.

# 33. Key Takeaways

### Web fundamentals

- Client sends requests.
    
- Server processes requests.
    
- Server sends responses.
    
- HTTP defines the communication format.
    

### Java

- Java programs execute on the JVM.
    
- Core Java supports networking.
    
- Core Java alone does not provide a convenient web application model.
    

### Servlets

- Servlets connect HTTP requests with Java code.
    
- Servlet Containers handle low-level web infrastructure.
    
- Tomcat, Jetty and Undertow are examples of Servlet Containers.
    

### Spring

- Spring provides an application framework/ecosystem.
    
- Spring Core provides IoC, Dependency Injection and bean management.
    
- Spring MVC simplifies web development.
    
- Spring Data simplifies persistence.
    
- Spring Security provides security infrastructure.
    
- Spring AOP handles cross-cutting concerns.
    
- Spring AI provides AI integration capabilities.
    

### Spring Boot

- Spring Boot is built on Spring.
    
- It reduces configuration.
    
- It provides auto-configuration.
    
- It provides starter dependencies.
    
- It can run with embedded servers.
    
- It uses sensible defaults.
    
- It makes Spring application development faster.
    

### Architecture

- Microservices are an architectural style.
    
- Spring Boot is commonly used to implement microservices.
